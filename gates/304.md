# #304：设备↔用户空间变换 API——旋转页/CropBox 落点偏移修复基座（2026-11-07，P1 / 审计 P2-4）

**背景**：标注落点流程（屏幕像素 → PDF 用户空间 → QuadPoints）隔着
四个变换：CropBox 偏移 / `/Rotate` 旋转 / Y 翻转 / DPI 缩放——修复前
**零设施**（PageGeometry 只有 MediaBox 宽高无原点无 CropBox；引擎
page_geometry 只读 MediaBox；渲染尺寸走 CropBox 显示域）。旋转页/
裁剪页上标注一定落错位置（审计 P2-4 维持，接 UI 前置）。

**实现**（分支 `feat/304-page-transform`，基于 main `7178eba`）：

- **新常开模块 `transform.rs`**（纯数学零引擎依赖——与 cache/render
  同纪律）：
  - `PageTransform { media: Rect, crop: Rect, rotate: Rotation }`
    （复用 annotation::Rect/Quad/Point + page::Rotation——issue 草图的
    `rotate: u16` 以仓内既有 typed 枚举代替）；
  - `screen_to_user` / `user_to_screen`：四旋转变换表（模块文档含
    推导锚点表 + 双向公式表）+ DPI 换算 + Y 翻转；DPI ≤ 0/非有限 →
    typed `TransformError::InvalidDpi`（不静默产出 NaN 落点——issue
    草图的无 Result 签名在此偏离，按仓内 typed 错误纪律走 Result）；
  - `rect_to_quads`：TL,TR,BL,BR 序（pdfd_writer.rs:222-228 实测
    约定同源）；
  - `screen_rect_to_user`：屏幕拖框（任意方向）→ 用户空间矩形
    （归一化 min/max——#302 标注 UI 的主消费面）；
  - `display_width_pt` / `display_height_pt`：CropBox 旋转归一显示域
    （FPDF_GetPageWidthF 同语义——与 rasterize 口径一致）；
- **trait 面**：`DocumentEngine::page_transform` 默认方法
  （`from_geometry` 诚实近似——trait 面零破坏，StubEngine 等 mock
  实现不动）；**`PdfiumEngine` 覆写**取真实双盒
  （`FPDFPage_GetMediaBox` + `FPDFPage_GetCropBox`——CropBox 缺失时
  pdfium 回落 MediaBox = 渲染显示域语义）+ `/Rotate`；
- **夹具**：`fixtures/rotated_crop.pdf`（514 字节，手写 xref 字节
  确定）+ 生成器 `gen_rotated_crop_fixture.py`：MediaBox [0,0,612,792] /
  CropBox [50,40,562,752]（非零偏移）/ /Rotate 90 / 红方块 @ 用户
  空间 [100,132,160,192]。

**公式正确性的三重验证**（关键——纯数学不能只靠推导自证）：

1. **锚点表锁**（常开单测 `rotate_anchor_table`）：四旋转 × 用户四角
   的显示落点逐角断言。**此锁抓到一个真 bug**：初版 θ=180 的 dy 公式
   写成 `cy1-uy`（上下翻转方向反了），锚点表红了才改对（`uy-cy0`）——
   证明锚点锁必要；
2. **真 pdfium 渲染互证**（pypdfium2 = 同一 C++ 引擎）：构造四旋转 ×
   偏移 CropBox PDF → 96 DPI 真渲染 → 位图找红方块像素中心 → 公式
   反算用户坐标 vs 真值：**误差 ≤ 0.5pt（= 2px 采样量化级），四旋转
   全过**；正向（用户真值 → 公式像素）误差 ≤ 0.7px；显示域尺寸
   pdfium 实测 vs 公式全等；
3. **夹具真 pdfium C API 读取验证**：`FPDFPage_GetMediaBox`/
   `FPDFPage_GetCropBox`/`FPDFPage_GetRotation` 对夹具的返回值逐项
   核对（Rust `page_transform` 将读的同一组调用）。

**诚实边界**：

- **引擎面 4 条测试本机未跑**：沙箱 pdfium 二进制（pypdfium2 自带
  chromium-140）与 pdfium-render 0.9.4 的 pdfium_7881 绑定面符号不
  兼容（`FPDFText_SetPositions` 等编辑 API 缺失 → dlsym 失败）。
  缓解：夹具的 pdfium 读取 + 渲染落点已用**同一 C++ 引擎**（Python
  绑定）逐项验证；Rust 引擎代码编译验证；CI windows-test 有正确
  pdfium 二进制，4 条测试 CI 上真跑。若 CI 红即回修（不等不猜）；
- `media` 仅观测面（像素映射只用 crop + rotate——渲染显示域即
  CropBox 域）；不做 CropBox ⊆ MediaBox 强校验（真实世界畸形容忍，
  数学自洽）；
- issue 草图签名偏离两处已述：`rotate: u16` → 仓内 typed `Rotation`
  枚举；`screen_to_user` 无 Result → typed Result（DPI 校验）。
  `rect_to_quads` 返回 `Quad`（仓内流通货币）而非裸 `[Point;4]`。

**CI 面**：windows-test 跑 `mdc-pdf --features engine-lopdf,
engine-pdfium`——引擎面新测试需 CI 的 pdfium 二进制（本地缺件的
如实登记）；常开面（transform 10 条）任何环境真跑。
